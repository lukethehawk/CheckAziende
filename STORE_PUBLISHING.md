# Store publication guide

CheckAziende 1.0.0 is prepared for distribution through the main browser-extension stores.

## Priority order

1. Firefox Add-ons (AMO)
2. Chrome Web Store
3. Microsoft Edge Add-ons
4. Opera Add-ons
5. Safari / App Store

Brave and Vivaldi can normally install the Chromium build from the Chrome Web Store, so they do not require a separate package.

## Generated packages

Run:

```bash
npm run build:stores
```

The build creates browser-specific directories under `dist/`.

The GitHub release workflow creates:

- `CheckAziende-<version>-firefox.zip`
- `CheckAziende-<version>-chrome.zip`
- `CheckAziende-<version>-edge.zip`
- `CheckAziende-<version>-opera.zip`

Firefox keeps the SVG toolbar icon and Mozilla-specific manifest declarations.

Chromium-derived builds remove Firefox-only manifest keys and use PNG toolbar icons.

## Firefox AMO

The Firefox build is the primary build.

The manifest declares the extension ID and Firefox data-collection categories required by the current AMO submission flow.

Recommended listing values:

- Name: CheckAziende
- Category: Search Tools / Productivity, depending on the available AMO taxonomy
- Homepage: https://github.com/lukethehawk/CheckAziende
- Support: https://github.com/lukethehawk/CheckAziende/issues
- Privacy policy: https://github.com/lukethehawk/CheckAziende/blob/main/PRIVACY.md

The source is not minified or transpiled; the distributed ZIP already contains readable source code.

## Chrome Web Store

Upload the Chrome ZIP generated by the build.

The Chromium manifest uses PNG action icons because Chromium does not support SVG toolbar icons in the manifest.

Dashboard privacy declarations must match `PRIVACY.md`.

## Microsoft Edge Add-ons

Use the Edge ZIP. It is generated from the same Chromium-compatible manifest.

Use the same privacy-policy and support URLs.

## Opera Add-ons

Use the Opera ZIP. It is generated from the Chromium-compatible package.

## Safari

Safari requires a separate Apple distribution workflow. The existing WebExtension code is the starting point, but packaging/signing and App Store submission should be handled separately after the Firefox/Chromium releases are approved.

## Store media still to prepare

Before submission, capture real screenshots from the final 1.0.0 build. Do not use mockups in place of product screenshots.

Suggested screenshots:

1. automatically identified company with financial cards;
2. company-data and balance-history sections;
3. manual VAT lookup / unidentified state.

Keep original screenshots in `store-assets/screenshots/` and create store-specific crops from those originals.
